# 易单来 2.3.13 核价工具 技术方案

## 1. 背景与目标

- 版本：易单来 2.3.13（核价智能体），计划上线 2026-10-31（Web + APP 同步发版）
- 依据：《易单来 V2.3.13 - 核价智能体 PRD》、2.3.13 需求评审会议纪要、Axure《20261010-智能核价-核价配置-v2.3.13》
- 目标：
  1. 核价角色由「APP 个人中心角色（业务员/销售管理）」改为「供应商端自定义使用角色」，原纸核算价格、原纸利用率、楞率均按使用角色配置；
  2. 楞型选项、加工费层数改为核价配置内固定维护，不再依赖大数据上架产品；
  3. 人工测算原纸价格支持含税/不含税设置；
  4. 对外报价计算口径统一保留 2 位小数；
  5. 提交审批/审批调价时展示调价空间与反算加工费；
  6. 审批详情布局调整、审批记录新增「层数楞型」「价格类型」列与导出。
- 范围：核价模块（APP 端 + 供应商端）。**量本利模块需求不在本文档范围内。**

> 本文档中 `【新增】` 表示新增字段/接口，`【修改】` 表示含义或逻辑有变化，`【废弃】` 表示前端不再使用（后端兼容保留一个版本）。
> 第 9 章为尚待产品确认的问题，文中对应处已按「默认方案」设计，确认后如有变化会同步更新。

## 3. 总体设计

### 3.1 角色解析（核心变化）

```
旧：appRole 请求头(salesman/manage/gm) → t_pricing_role_price.role_code → 核算价格/成本明细权限
新：当前用户 userId → t_pricing_usage_role_member → 使用角色 → 核算价格/成本明细权限/原纸利用率/楞率
```

- 一个员工在同一供应商下最多属于一个使用角色，因此「当前用户 → 使用角色」唯一确定。
- `appRole` 请求头**不再参与**核价价格口径与成本明细权限判断；仅保留给客户搜索（业务员看自己名下 / 销售管理看全部）等原有用途。
- 审批流程节点（销售负责人/总经理）与使用角色**无关**，仍按审批配置的节点员工流转。

### 3.2 原纸成本取数矩阵

| 取数源           | 原纸价格                       | 含税设置          | 原纸利用率  | 楞率     |
| ------------- | -------------------------- | ------------- | ------ | ------ |
| 固定取人工测算价格（默认） | 使用角色的核算价格（库存/市场/外部）        | 生效（不含税 ×1.13） | 使用角色配置 | 使用角色配置 |
| 跟随量本利配置       | 量本利配置的价格类型（移动加权/个别计价/人工测算） | 仅当量本利为人工测算时生效 | 使用角色配置 | 使用角色配置 |

> 原纸利用率、楞率在两种取数源下均取使用角色配置（不再取量本利成本配置的利用率、不再取 `t_budget_config_flute_rate`）。见 9 章 Q1。

### 3.3 核价主流程（新）

1. 进入核价页 → `app/pricing/getConfig` 返回当前用户的使用角色；为空则前端提示「未配置后台使用角色，无法核价」并禁止核价。
2. 输入材料代码 → `app/pricing/parseMaterialCode`：解析层数/角色 → 楞型选项（取楞型选项配置）+ 当前角色楞率 → 每层单平方价（按角色口径、含税换算）→ 默认加工费（后端按新规则匹配后返回）。
3. 调整参数 → `app/pricing/calculate`：后端再次校验使用角色，按 4.1 公式计算并保存核价记录。
4. 提交审批 → 前端修改提交价格时调用 `app/pricing/calcProcessingFee`（不传 `approvalId`）展示调价后加工费；后端提交时同口径计算，**覆盖 `processing_fee` 并重算记录成本字段**，原值保留在 `original_processing_fee`。
5. 审批 → `getApprovalDetail` 返回按审批人角色重算的 `approvalBreakdown`；打开详情及审批人修改价格时调用 `app/pricing/calcProcessingFee`（传 `approvalId`）展示审批人口径加工费；`approve` 时后端同口径计算并落库审批节点的调价后加工费。

## 4. 核心业务规则

### 4.1 计算公式与精度

记 `D` = 价格精度：**核算价格为外部报价（external）时 D=2，否则 D=4**；最终价格（底价/牌价/一口价/折扣后价）统一保留 2 位。均为四舍五入。

| 项            | 公式                                                  | 精度  |
| ------------ | --------------------------------------------------- | --- |
| 单平方原纸价       | 吨价 × 克重 / 1,000,000；若该价格类型在含税设置中为「不含税」，再 × 1.13     | D   |
| 面纸/中隔纸/里纸层成本 | 单平方原纸价                                              | D   |
| 瓦纸层成本        | 单平方原纸价 × 角色楞率                                       | D   |
| 原纸成本合计       | Σ 各层成本                                              | D   |
| 含利用率原纸成本     | 原纸成本合计 ÷ (角色原纸利用率 ÷ 100)                            | D   |
| 小计           | 含利用率原纸成本 + 加工费 + 运费                                 | D   |
| 牌价/一口价/折扣    | 与 2.3.10 一致（牌价 = 小计 / (1 - 返利%)，一口价 = 小计，折扣按百分比/直减） | 2   |

### 4.2 调价后加工费（反算）

```
调价后加工费 = 提交价格(调价后) × (1 - 返利%) - 含利用率原纸成本 - 运费      保留 2 位
```

- 提交/重新提交时（提交人口径）：含利用率原纸成本、运费、返利均取核价记录（`paper_cost_with_util / freight / rebate`）。
- 审批时（审批人口径）：含利用率原纸成本取按**当前审批人**使用角色重算的 `approvalBreakdown.paperCostWithUtil`（口径一致或审批人无角色时取核价记录），运费、返利沿用核价记录。
- 提交价格类型为「一口价」时返利按 0 处理（一口价本身未做返利上浮）。见 9 章 Q6。
- **计算口径只在后端一处实现**：抽取公共方法供 `calcProcessingFee`（实时展示）与 `submitApproval/resubmitApproval/approve`（落库）共用，前端不自行计算；原纸成本、运费等不再为反算而额外下发，成本明细权限不受影响。

**落库口径（`t_pricing_record`）**

| 字段                        | 写入时机                    | 含义                          |
| ------------------------- | ----------------------- | --------------------------- |
| `original_processing_fee` | 核价计算保存记录时写入，之后不再修改      | 原加工费（核价时匹配/录入的加工费），始终有值     |
| `processing_fee`          | 核价计算时 = 原加工费；提交审批调价时被覆盖 | 当前加工费（调价过即为调价后加工费），所有展示处直接取 |

- 提交/重新提交审批时，若提交价格 ≠ 默认价格：按上式反算加工费，覆盖 `processing_fee`，并用新加工费调用 `calculateBreakdown` **同步重算并覆盖** `subtotal / rebate_amount / base_price / discount_amount / fixed_discount_amount / list_price(_before_discount) / fixed_price(_before_discount)`，保证同一行成本数据自洽；提交价格 = 默认价格时，`processing_fee` 恢复为 `original_processing_fee` 并按原值重算。
- 反算只依赖提交价格、含利用率原纸成本、运费、返利，不依赖上一次的 `processing_fee`，多次重新提交不会累计偏差。
- 「默认价格」（调价空间校验基准、提交页默认回显）一律按 `original_processing_fee` 计算，不得使用已被覆盖的 `processing_fee`。
- 审批人调价（审批人口径）**不覆盖** `t_pricing_record`，只写 `t_pricing_approver_node.after_processing_fee`（见 9 章 Q14）。
- 是否调价：`processing_fee ≠ original_processing_fee`。

### 4.3 加工费匹配

1. 加工费支持修改且用户传值 → 取用户值；
2. 否则按层数匹配特殊原纸加工费：**奇数层取第 1 层（面纸）原纸代码；偶数层（2/4/6）取最后一层（里纸）原纸代码**；
3. 无特殊原纸配置 → 取该层数默认加工费；
4. 无默认加工费 → 按 **0** 处理，允许正常核价（加工费不可修改时也可核价）。

### 4.4 楞型选项（固定枚举，配置时多选）

| 层数      | 可选楞型                                        |
| ------- | ------------------------------------------- |
| 2 / 3 层 | A、B、C、E、F                                   |
| 4 / 5 层 | AA、AB、AC、AE、BB、BC、BE、CC、CE、EE、EB            |
| 6 / 7 层 | BAA、BAB、BAC、BCA、BCB、BCC、BEE、CAC、CEB、EBA、EBC |

- 楞型选项配置为空的层数，APP 端解析该层数材质时无可选楞型，提示「该层数未配置楞型选项」。
- 楞型选项中的单楞均在 A/B/C/E/F 范围内，与楞率配置一一对应（2/3 层已去掉 D 楞）。

### 4.5 材料代码解析（分隔符调整）

- 原纸代码允许包含「+」，因此**材料代码分隔符去掉「+」**，仅保留 `/`、`,`、`，`、空格、换行；
- 输入含上述分隔符时按分隔符拆分，每段作为一层原纸代码；不含分隔符时按原纸代码集合最长匹配；
- 「+」作为原纸代码的普通字符参与匹配（如原纸代码 `K+`）。

### 4.6 审批价格重算（审批详情）

- 解析审批人（当前登录用户）的使用角色；若与提交人记录快照的「核算价格 + 含税 + 利用率 + 楞率」任一不一致，则按审批人口径重算 `approvalBreakdown`（原纸价格、利用率、楞率均取审批人角色，加工费/运费/返利/折扣沿用记录），前端展示「审批价格 / 原有价格」tab；完全一致时 `approvalBreakdown` 返回 null，不展示 tab。
- 审批人不属于任何使用角色时，`approvalBreakdown` 返回 null（仅展示原有价格）。
- 提交后成本明细：`breakdown` 直接取记录字段（`processingFee` 即当前加工费，小计及后续价格已在提交时同步重算），新增 `originalProcessingFee` 取 `original_processing_fee`；前端在两者不相等时展示「原加工费」。
- 审批人口径重算 `approvalBreakdown` 时，加工费沿用记录的 `processing_fee`（即提交人调价后的加工费）。

### 4.7 配置保存校验

| 校验                                   | 提示                     |
| ------------------------------------ | ---------------------- |
| 使用角色数量为 0                            | 使用角色未配置                |
| 使用角色数量 > 10                          | 角色数超出上限                |
| 角色名称为空 / 超过 10 字                     | 角色名称未填写 / 角色名称最多 10 个字 |
| 单角色成员 > 50                           | 超出人员上限                 |
| 同一员工出现在多个角色                          | 「{姓名}」已在其他角色中          |
| 角色原纸利用率为空 / 不在 (0, 999.9999]         | 角色原纸利用率未设置             |
| 角色楞率 A/B/C/E/F 任一为空 / 不在 [0, 9.9999] | 楞率配置未完善                |
| 加工费层数不在 2~7 / 重复                     | 加工费层数不合法 / 加工费层数重复     |
| 同层数特殊原纸重复                            | 已存在该原纸纸种的加工费配置         |
| 楞型选项不在 4.4 枚举范围                      | 楞型选项不合法                |

> 角色成员可为空（空角色不影响保存，但无人可用该角色核价）。

### 5.3 数据迁移

- 旧 `t_pricing_role_price`（role_code = salesman/manage/gm）无法映射到自定义角色，上线后不再生效。
- **上线后各供应商必须先完成「使用角色 + 原纸利用率 + 楞率 + 楞型选项」配置，否则 APP 端无法核价**，需运营提前通知/协助配置（见 9 章 Q2）。
- 历史核价记录原加工费回填（历史数据未做过调价落库，`processing_fee` 即原加工费）：

```sql
UPDATE `t_pricing_record`

WHERE `original_processing_fee` IS NULL;
```

| price      | BigDecimal | 是  | 调价后价格（元/㎡，2 位小数）：提交页为提交价，审批页为审批后价格；本接口不做 0~99.99 范围校验，由提交接口校验 |
| priceType  | String     | 是  | 价格类型：list-牌价 / fixed-一口价；审批页传记录的 `submittedPriceType`       |

出参 `ProcessingFeeCalcVo`：

| 字段                  | 类型         | 说明                                                       |
| ------------------- | ---------- | -------------------------------------------------------- |
| beforeProcessingFee | BigDecimal | 调价前加工费：提交人口径为 `original_processing_fee`；审批人口径为核价记录当前 `processing_fee` |
| afterProcessingFee  | BigDecimal | 调价后加工费，按 4.2 公式计算，保留 2 位（可能为负数，见 9 章 Q16）                     |

逻辑：

1. 不传 `approvalId`：校验核价记录存在且核价人为当前用户；含利用率原纸成本、运费、返利取核价记录。
2. 传 `approvalId`：校验审批节点属于该核价记录且审批人为当前用户；含利用率原纸成本按当前审批人使用角色重算（同 `getApprovalDetail.approvalBreakdown`，口径一致或审批人无角色时取核价记录），运费、返利取核价记录。
3. `priceType = fixed` 时返利按 0。
4. 与 `submitApproval/resubmitApproval/approve` 共用同一计算方法，保证展示值与落库值一致。
